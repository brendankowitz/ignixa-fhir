# FHIR R6 Ballot4 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump the repo's FHIR R6 support from `hl7.fhir.r6.core#6.0.0-ballot2` to `#6.0.0-ballot4`, regenerate every R6-derived artifact, repoint the `fhir-codegen` submodule at its new GitHub home, and update the docs/tests that reference the pinned version.

**Architecture:** All R6 schema/search/valueset/compartment/codesystem artifacts are generated by running `codegen/Ignixa.Specification.Generators` (a custom `ILanguage` implementation) against a FHIR package resolved by the vendored `fhir-codegen` tool (git submodule `third-party/fhir-codegen`, aliased at path `codegen/fhir-codegen`). Bumping the version is: (1) edit 3 hardcoded pin strings, (2) re-run each generation mode for R6, (3) fix any consumer code broken by structural spec changes between ballot2 and ballot4, (4) update docs/tests/ADR.

**Tech Stack:** .NET 8 (codegen tool) / .NET 9+ (main solution), PowerShell 7+ / Bash, git submodules.

## Global Constraints

- Version pin changes everywhere: `6.0.0-ballot2` → `6.0.0-ballot4`. Do not touch R4/R4B/R5/STU3 pins.
- `dotnet build All.sln` must end at 0 warnings, 0 errors (per repo CLAUDE.md checklist).
- `dotnet test All.sln` must pass in full before the plan is considered done.
- All generation commands run from the repo root (`E:\data\src\ignixa-fhir`) — the generator resolves relative output paths against the process's current working directory, not the tool's own binary location.
- Do not change the pinned commit of `third-party/fhir-codegen` beyond what the remote move requires — no unrelated submodule version bump.
- `R6CoreSchemaProvider.Partial.cs` is hand-maintained; never regenerate or overwrite it.
- This repo has previously had codegen output land in the wrong folder or under a drifted namespace — every regeneration task in this plan includes an explicit folder/namespace verification step. Do not skip these even though they feel redundant with the build step; a wrong-namespace file can still compile (as an unused duplicate type) without a build error.
- Commit after every task.
